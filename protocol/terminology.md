# UTP Terminology

This document defines the core terminology used throughout the Universal Cloud Transfer Protocol (UTP).

* **Storage Provider (Provider)**: An implementation of the UTP interface that interacts with a specific underlying storage backend (e.g., `LocalProvider`, `GoogleDriveProvider`, `S3Provider`).
* **Resource Identifier (URI)**: A universal string representing a file or directory on a specific provider.
* **Transfer**: A tracked data movement operation from a Source URI to a Destination URI.
* **Chunk**: A contiguous byte-range of a file. UTP breaks large files down into discrete chunks to enable concurrency, backpressure, and resumability.
* **Chunk Plan**: A mapped sequence of `ChunkTask` structures generated by the engine by mathematically comparing the sizes and limits of the source and destination providers.
* **State Manager**: The durable tracking layer (often implemented via a relational database) that records the exact byte-progress and chunk states of active transfers.
* **ReadStream / WriteSession**: Ephemeral session tokens issued by Providers to track the internal HTTP/file handles needed to perform I/O for a specific chunk or file.
* **Backpressure**: The mechanism of slowing down chunk ingestion from the Source when the Destination (or memory) is saturated.
* **Exponential Backoff**: The retry strategy used by the Engine when encountering transient (retryable) errors from a Provider.
