Privacy Policy for Cloud Transfer Protocol

Application Name: Cloud Transfer Protocol (CTP) · Effective Date: November 23, 2026 · Author: Arpit Nayak · Homepage: https://ctp.arpitnayak.tech
ZERO-DISK & VOLATILE RAM PIPELINE GUARANTEE Cloud Transfer Protocol (CTP) is an open-source, client-side data migration engine. We operate zero intermediary relay servers, store zero payload bytes on disk, collect zero user analytics or telemetry, and never transmit your cloud credentials or files to any third party. Data moves directly from your source cloud into volatile RAM and immediately into your destination storage via direct TLS 1.3 socket connections.

1. Purpose of the Application

Cloud Transfer Protocol (CTP) is designed to solve a fundamental efficiency and bandwidth problem in multi-cloud workflows: transferring files between distinct cloud providers (such as Google Drive, Microsoft OneDrive, Amazon S3, and Cloudflare R2) without requiring users to download massive payloads to their local storage drives first.

The application is 100% public, free, open-source, and does not require users to create an account, register, or log into a web service to view information or use the software.

2. Google User Data Accessed & Requested Scopes

When you choose to connect Google Drive to Cloud Transfer Protocol, the application requests access via Google OAuth 2.0. The specific scopes requested are:

  • https://www.googleapis.com/auth/drive.readonly — Used strictly to discover, list, and read files that the user specifically selects for transfer.
  • https://www.googleapis.com/auth/drive.file — Used strictly to create and write files in Google Drive when Google Drive is chosen as the destination target by the user.

Specific Data Points Accessed:

  • File Metadata: File IDs, file names, sizes, and MIME types strictly necessary to calculate chunk boundaries and display progress to the user.
  • File Content: Streamed chunk-by-chunk in volatile memory (RAM ring buffers) solely during active user-directed transfer operations.
  • User Identity: Email address associated with your Google account (strictly used locally to differentiate between multiple connected accounts in your CLI configuration).

3. How Google User Data is Used & Handled

Cloud Transfer Protocol handles Google user data strictly according to the following principles:

  • User-Directed Execution: Data is only accessed when you explicitly initiate an operation (such as utp transfer, utp sync, or utp ingest).
  • In-Memory Streaming (Zero-Disk): File chunks read from Google APIs are held in ephemeral RAM buffers only for the milliseconds required to pipe them into the destination cloud socket. File content is never written to disk, never cached on local drives, and never saved to any database.
  • Direct Encrypted Peer-to-Cloud Transmission: Network traffic flows directly between your machine and Google's official API endpoints (www.googleapis.com) using TLS 1.3 encryption. No intermediate proxy, relay server, or telemetry backend is ever used.

4. Google API Services User Data Policy (Limited Use Disclosure)

MANDATORY LIMITED USE DISCLOSURE Cloud Transfer Protocol's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

In strict adherence to the Limited Use requirements:

  1. No Human Inspection: We do not allow humans to read user file data or metadata unless required by applicable law or authorized by you for specific troubleshooting.
  2. No Advertising: Google user data is never used or transferred for serving advertisements, retargeting, personalized advertising, or market research.
  3. No Third-Party Sharing: We never sell, rent, or transfer Google user data to data brokers, analytics providers, or any third party. Data is transferred strictly to the cloud destination you explicitly configure (e.g., your own OneDrive or AWS bucket).
  4. No AI/ML Model Training: Google user data is never used to train, develop, or improve generalized Artificial Intelligence (AI) or Machine Learning (ML) models.

6. Credential Storage, Data Retention & Deletion

Local Storage of OAuth Tokens:
OAuth 2.0 access and refresh tokens returned by Google are stored strictly on your local computer in your user profile directory (e.g. .utp_gdrive_token.json). They are protected by local filesystem access controls and are never uploaded to any remote server.

Data Retention:
Because Cloud Transfer Protocol does not operate backend databases or cloud servers, we retain zero personal data or file content. File chunks in RAM are immediately wiped upon transfer completion.

How to Delete Data & Revoke Access:

  • Revoke Google Access: You can revoke Cloud Transfer Protocol's access at any time by visiting your Google Account Security Settings at https://myaccount.google.com/permissions.
  • Delete Local Credentials: You can permanently remove all stored credentials by deleting the local token files from your machine:
    rm ~/.utp_*_token.json (Linux/macOS) or Remove-Item ~\.utp_*_token.json (Windows PowerShell).

7. GDPR, CCPA & International Privacy Standards

Under the General Data Protection Regulation (GDPR) and California Consumer Privacy Act (CCPA), users possess the right to data minimization, privacy by design, and deletion. Because Cloud Transfer Protocol collects zero personal data on external servers, operates on a zero-knowledge architecture, and writes no file data to persistent storage, it inherently satisfies the strictest requirements of international privacy regulations.
